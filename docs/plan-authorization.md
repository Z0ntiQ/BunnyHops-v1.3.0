# План фичи: вкладка «Авторизация» (Bunny Hops)

Статус: **запланировано, не начато**. Идея зафиксирована 2026-11-03 по скриншоту Postman (вкладка «Авторизация» с выпадашкой «Метод авторизации»: Inherit, None, Basic Auth, Digest Auth, Bearer, OAuth 2.0, API Key, AWS Signature, HAWK, JWT). Приоритет и срок не назначены — это план «на будущее».

## Зачем
Сейчас авторизацию в Bunny Hops гоняют вручную: Basic — сам base64 в заголовок, Bearer — руками в Headers или через `{{token}}` из Scenario. Это работает, но каждый раз требует ручной работы и не переиспользуется между запросами сценария. Вкладка «Авторизация» с явным типом — привычная пользователю модель из Postman.

## Где в коде (точка входа)
- Табы запроса: ряд `.tab` в `frontend/src/app.rs` (Params/Headers/Scenario/Vars) — добавить таб «Auth» в тот же ряд и `<Show when=tab=="auth">` в тот же блок.
- UI-примитивы уже есть: собственный dropdown (`MethodSelect` в `app.rs` — кнопка + div-меню, пропсы через `Callback`; `<select>` не использовать — браузеры не стилизуют `<option>`), `KvEditor` (`frontend/src/ui.rs`) для пар ключ-значение (API Key, OAuth-формы).
- Модель запроса: структура шага сценария и главный запрос держат method/url/headers/body — добавить поле `auth {type, params}`; применение — **до** отправки в `/proxy`: заголовок Authorization / query-параметр встраиваются на клиенте (wasm), сервер `/proxy` не трогаем.
- Персистентность: state уже сериализуется в localStorage (`hop.*`) — новое поле подхватится автоматически; ключи не переименовывать.

## Этапы (оценки — чистое время реализации с проверкой в браузере)

### Этап 1 — каркас + простые методы. ~2–4 часа (~1 вечер)
- Вкладка «Auth», dropdown типа (переиспользовать паттерн MethodSelect), формы per-type.
- **None** — явно без авторизации.
- **Basic Auth** — `Authorization: Basic base64(user:pass)`. Нужен base64 (в коде уже есть бэза для base64 — грепнуть `b64` в `logic.rs`; при отсутствии — crate `base64`).
- **Bearer** — `Authorization: Bearer <token>`, поддержка `{{vars}}` в токене.
- **API Key** — имя+значение, выбор: в заголовок или в query (query — дописать в params-синхрон).
 Это ~80% реальной пользы (Basic/Bearer/API Key закрывают почти все рабочие API).

### Этап 2 — крипто-методы без браузер-флоу. +3–5 часов
- **Digest Auth** — challenge-response: 401 → распарсить `WWW-Authenticate` → повтор с `Authorization: Digest …`. Нужна crate `md-5` (wasm-ok). ВНИМАНИЕ: повторный запрос идёт через `/proxy` — прокси не должен «съедать» 401 (он стримит статус цели один в один — ок).
- **JWT (подпись)** — генерация подписанного JWT (HS256): `hmac` + `sha2` (wasm-ok), payload из формы.
- **HAWK** — HMAC + timestamp/nonce по RFC 7235-секции HAWK; формула, тест-векторы из RFC.

### Этап 3 — тяжёлые. Полдня–день, из них OAuth ~⅓
- **AWS Signature v4** — канонический запрос + цепочка HMAC (`hmac`+`sha2` уже появятся на этапе 2). Отладка «почему 403» дороже кода — заложить время на сверку с real AWS или тест-векторами SigV4 из документации AWS.
- **OAuth 2.0**:
  - client_credentials / password grant — ~2 часа: POST за токеном через `/proxy`, кэш токена с `expires_in`, автоподстановка Bearer.
  - authorization code flow — отдельная подсистема: редирект в браузер, приём callback на `localhost:3000` (добавить роут в `src/main.rs`), хранение/refresh. Делать только если реально нужен; не начинать без явного решения пользователя.

## Inherit
В Postman — наследование из коллекции. У нас аналог — наследование от «главного запроса» для шагов сценария: шаг без своего auth берёт auth родителя. Реализовать как значение `Inherit` в модели шага на этапе 1 (дешево), семантику коллекции не выдумывать.

## Сквозные правила реализации
- Все токены/секреты — в localStorage вместе со запросом; в UI маскировать парольные поля (`type=password`).
- Поддерживать `{{name}}`-подстановку во всех полях auth (единая точка `substitute` из `logic.rs`).
- Проверка каждого метода — живым запросом к httpbin (`/basic-auth`, `/digest-auth`, `/bearer`) через браузер, реальные клики по координатам (JS-`.click()` в Leptos не работает — см. скилл bunny-hops).
- UI-конвенции пользователя: без подсказок-заглушек; выпадки — свои компоненты с заливками; зум не трогать.

## Итоговая оценка
Практичный набор (None/Basic/Bearer/API Key/Digest/JWT/HAWK + Inherit) — ~1 день работы. Полный список со скриншота (плюс AWS Sig V4 и OAuth 2.0 с браузерным флоу) — 1.5–2 дня. Начинать с этапа 1 только по явной команде пользователя.
